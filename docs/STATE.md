## 3. Канонический деплой — единственный разрешённый путь

1. Правки **только в `src/`** этого репо (после `git pull`).
   Патчи в минифицированные чанки `_next/…` **запрещены** — это метод до 03.11,
   он привёл к потере недели правок (см. § 8).
2. Деплой: `bash scripts/deploy_spacecam.sh "описание правки"` — скрипт сам:
   pull → синк исходников репо → рабочее пространство → `bun run build`
   (static export, `NEXT_PUBLIC_BASE_PATH=/SpaceCam`) → статика в корень репо
   (проектные файлы `src/`, `scripts/`, `docs/*.md`, `docs/sql`, `docs/backup`
   И корневые конфиги сборки `package.json`, `bun.lock`, `tsconfig.json`,
   `next.config.ts`, `postcss.config.mjs`, `next-env.d.ts` защищены от удаления
   rsync --delete; без исключений первый же деплой стёр бы конфиги «источника
   истины» — найдено dry-run 04.11 и усилено до выкатки) → commit → push.
   ⚠️ Постаревший `public/` workspace синхронизируется из корня репо АВТОМАТИЧЕСКИ
   (шаг 2.5 скрипта; добавлен 05.11 после инцидента `7194dcc`: сборка из старого
   `public/` стёрла с прода 304 фото, 49 паспортов PDF, дилеров, бренд rsafe,
   solutions — всё восстановлено коммитом `990b440`). Чужой `node_modules`
   после отката лечится `bun install` (скрипт делает сам перед сборкой).
3. Через 1–3 мин (кеш Pages `max-age=600`): `python3 scripts/verify_deploy.py` —
   live должен совпасть с репо по хешам ключевых файлов и топ-чанков.
4. Несовпало — НЕ откатывать деплой: разбираться (кеш браузера — Ctrl+F5, `?v=<commit>`;
   Pages ещё собирает; реально другой коммит — тогда `git log`).
5. Директива владельца (04.11): перед каждым пушем/деплоем — краткие релиз-нотес
   и вопрос «выкатываем на GitHub или продолжаем дорабатывать»; источник исходников
   для любой задачи — всегда текущий `main` на GitHub (никаких откатов функционала).

## 4. Восстановление с нуля (если песочница потеряла всё)

1. `git clone https://github.com/andreyshalnov/SpaceCam.git` — репозиторий
   самодостаточен: `src/` + конфиги + статика + `scripts/` + документация.
2. Сборка: `bun install`; `public/` в репо не дублируется (383 МБ) — восстановить
   из корня репо (там вся статика public: `products/`, `brands/`, `dealers/`,
   `docs/*.pdf`, логотипы, `robots.txt`) → `NEXT_EXPORT=1 NEXT_PUBLIC_BASE_PATH=/SpaceCam bun run build`.
3. БД — живая в Supabase, ничего восстанавливать не нужно. Если БД потеряна:
   дампы у владельца, схема — `docs/sql/20261103_objects_schema.sql` +
   `docs/sql/20261103_security_fix_grants.sql`.
4. Аккаунты: CSV с паролями у владельца (`accounts_spacecam_20261103.csv`).
   Новые — через Auth admin API (service-ключ).
5. Проверка: `python3 scripts/verify_deploy.py`.
